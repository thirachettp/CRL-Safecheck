# SafeCheck — ต้นแบบ Phase 1

ต้นแบบสำหรับทดสอบว่า concept หลักใช้ได้จริง: ตั้งต้นข้อมูลธงอพยพ รับข้อมูลคนในพื้นที่จาก MS Form เปิดเหตุการณ์ (จริงหรือซ้อม) ให้ผู้นำธงเช็กชื่อบนมือถือ และดูภาพรวมสด

| ฟังก์ชัน | หน้า |
| --- | --- |
| 1. ตั้งต้นข้อมูลธง + เมนูซ้อม | `/setup` นำเข้า Excel แผนอพยพทุกแผนก, จับคู่อีเมลกับรหัสพนักงาน, เริ่มซ้อม, ประวัติการซ้อม |
| 2. รับข้อมูลจากแหล่งต่างๆ (MS Form, Driver) | `/sources` ดึงจาก SharePoint List, นำเข้า Excel ของฟอร์ม, จำลองคนส่งฟอร์ม, ดึงรถในลานจาก KIOS |
| 3. SafeCheck | `/incidents` เปิดเหตุการณ์, `/incidents/[id]` หน้าผู้บัญชาการ, `/incidents/[id]/flag/[ธง]` หน้าผู้นำธง |
| 4. Dashboard | `/` เหตุการณ์ที่เปิดอยู่, กำแพงธง, ยอดชาย/หญิง, ความสดของข้อมูล, ผลการซ้อม |

## Deploy บน Vercel

1. อัปโหลดโฟลเดอร์นี้ขึ้น GitHub (repo แบบ private)
2. Vercel → Add New Project → เลือก repo → Framework จะขึ้น Next.js เอง
3. แท็บ Storage → เพิ่ม **Neon** (Postgres) → Vercel ใส่ `DATABASE_URL` ให้อัตโนมัติ
4. Settings → Environment Variables ใส่อย่างน้อย
   - `APP_USER`, `APP_PASSWORD` — **ต้องตั้ง** เว็บมีข้อมูลพนักงาน ห้ามเปิดสาธารณะ
   - ค่าอื่นดู `.env.example`
5. Deploy — ตารางในฐานข้อมูลสร้างเองตอนเรียกครั้งแรก ไม่ต้องรัน migration

หมายเหตุ:
- `vercel.json` ตั้ง region เป็น `sin1` และ cron วันละครั้งตอน 09:00 เวลาไทย (02:00 UTC) เพื่อให้ deploy บน Hobby ได้
- อยากให้ดึงทุก 15 นาทีโดยไม่ขึ้น Pro: ใช้ตัวตั้งเวลาภายนอกฟรี เช่น cron-job.org เรียก `GET https://<โดเมน>/api/cron/sync` ทุก 15 นาที พร้อม header `Authorization: Bearer <CRON_SECRET>` (ตั้ง `CRON_SECRET` ใน Vercel ก่อน)
- ถ้าขึ้น Pro ภายหลัง เปลี่ยน schedule ใน `vercel.json` เป็น `*/15 * * * *` แล้วเลิกใช้ตัวตั้งเวลาภายนอก
- ต้นแบบนี้ใช้ Basic Auth ทั้งเว็บ เบราว์เซอร์มือถือจะถามรหัสครั้งแรกแล้วจำไว้ ระบบจริงควรเปลี่ยนเป็น Sign in with Microsoft

## ลองใช้ครั้งแรก (ประมาณ 10 นาที)

1. `/setup` ลากไฟล์ทั้ง 43 ไฟล์จากโฟลเดอร์ “รายชื่อแผนฉุกเฉินตามแผนก” เข้าไป ดูรายการปัญหาแล้วกดบันทึก
2. `/sources` นำเข้า Excel ของฟอร์ม Check (In-Out) หรือกด “ส่งฟอร์มทดสอบ” สักสองสามคน
3. `/setup` ส่วนจับคู่อีเมล ใส่รหัสพนักงานให้อีเมลที่ส่งฟอร์มเข้ามา
4. `/setup` กด “เริ่มซ้อมอพยพ” → หน้าผู้บัญชาการเปิดขึ้น กดธงใดก็ได้เพื่อเปิดหน้าผู้นำธง (ส่งลิงก์นี้ให้คนอื่นเปิดบนมือถือได้)
5. เช็กชื่อจนครบ ระบบบันทึกเวลานับครบ แล้วกดปิดเหตุการณ์

## เส้นทาง MS Form (non-premium)

```
คนส่งฟอร์ม → Power Automate (standard) → SharePoint List SafeCheck_DIV_CheckIn
          → แอพดึงผ่าน Graph delta ทุก 15 นาที และทันทีที่เปิดเหตุการณ์
```

ต้องมี app registration จาก IT สิทธิ์ `Sites.Selected` บน site CDSBangnaWarehouse แล้วใส่ `MS_TENANT_ID`, `MS_CLIENT_ID`, `MS_CLIENT_SECRET`, `SP_SITE`, `SP_DIV_LIST` ระหว่างรอ ใช้การนำเข้า Excel ของฟอร์มแทนได้ ทั้งสองทางใช้ Id คำตอบเดียวกัน จึงไม่นับซ้ำ

คอลัมน์ใน list: `ResponseId` (หรือใส่ใน Title), `Email`, `FullName`, `Gender`, `Site`, `SubmittedAt` (UTC) ถ้าชื่อ internal ไม่ตรง ตั้ง `SP_FIELD_MAP`

ถ้าเลือกทาง Premium ภายหลัง: ให้ Flow ยิง `POST /api/ingest/div` พร้อม header `X-Sync-Token` (= `INGEST_TOKEN_DIV`) และ `X-Batch-Id`

## เส้น Driver (KIOS)

แอพเรียก RPC เดียวกับสูตร Power Query ใน Power BI โดยตรง ไม่ผ่าน Power BI:
`POST {KIOS_BASE_URL}/rest/v1/rpc/vms_dpark_withtransaction_detail?status_id=eq.2` พร้อม header `apikey`

- ใช้ **ทะเบียนรถ** เป็นตัวระบุ (`plate:<ทะเบียน>`) หนึ่งคันนับหนึ่งคน ทะเบียนที่พิมพ์ต่างกัน (ขีด เว้นวรรค) นับเป็นคันเดียว รถคันเดียวหลายรายการขนส่งเหลือรายการที่เข้าล่าสุด
- ระบบหาคอลัมน์ทะเบียน จังหวัด ชื่อคนขับ เบอร์ บริษัท โซน เวลาเข้าลานเอง ดูผลได้ที่ `/sources` ถ้าจับผิดให้ตั้ง `KIOS_FIELD_MAP`
- เป็น snapshot ทั้งชุดทุกรอบ ถ้าจำนวนรถลดลงเกิน 30% จากรอบก่อน ระบบกักไว้และใช้ข้อมูลรอบก่อน จนกว่าจะกด “รับข้อมูลรอบนี้” ที่ `/sources`
- เลือกได้ว่าคนขับไปรวมที่ธงไหน (ตั้งที่ `/sources`) ไม่เลือก = ไม่ระบุธง
- รถที่ออกจากลานระหว่างเหตุการณ์ไม่ถูกลบจากรายชื่อ แต่ติดป้าย “รถออกจากลานแล้ว?”
- ถ้าสูตร Power Query ส่ง `Body` ที่มีพารามิเตอร์ ใส่ค่าเดียวกันใน `KIOS_RPC_BODY`

## กฎที่ระบบใช้

**เข้า/ออกจากฟอร์ม** (`lib/presence.ts`): รายการแรก = เข้า, ส่งซ้ำใน 10 นาทีนับครั้งเดียว, ครั้งที่สองในไซต์เดิม = ออก, ต่างไซต์ = ย้ายไซต์, ครบ 14 ชม. = ออกอัตโนมัติ, จับคู่ตามช่วง 14 ชม. ไม่ใช่วันปฏิทิน

**เปิดเหตุการณ์** (`lib/incident.ts`):
- snapshot รายชื่อจากข้อมูลที่มีอยู่ทันที ไม่รอ network แล้วจึงดึงสดตามมา
- merge บวกอย่างเดียว ห้ามลบคน ห้ามทับสถานะที่กดแล้ว คนที่หายจากแหล่งข้อมูลติดป้าย “อาจไม่อยู่ในพื้นที่”
- ทุกการเปลี่ยนสถานะเก็บ log พร้อมชื่อคนกดและเวลา
- เหตุการณ์ที่ปิดแล้วแก้ไม่ได้

**การอ่านไฟล์ธง** (`lib/parsers.ts`): หาแถวหัวตารางจากคำว่า “รหัสพนักงาน” เอง ใช้เบอร์ธงใหม่ ในไฟล์จริงคอลัมน์ “คำนำหน้า” เก็บชื่อจริงและ “ชื่อ-นามสกุล” เก็บนามสกุล ระบบรองรับทั้งสองแบบ คนที่อยู่หลายไฟล์ใช้ค่าจากไฟล์แรกและแจ้งเตือน

## ข้อจำกัดของต้นแบบ

- ยังไม่มีเส้น Cnext และ Outsource — ระหว่างนี้ให้เปิดเหตุการณ์แบบ “รวมทุกคนในแผนอพยพ”
- เส้น Driver นับหนึ่งคันหนึ่งคน ผู้ช่วยคนขับหรือผู้โดยสารยังไม่ถูกนับ
- อัปเดตหน้าจอด้วยการถามซ้ำทุก 3 วินาที ยังไม่ใช่ realtime และยังไม่มีโหมด offline
- ไฟล์ Excel อ่านในเบราว์เซอร์ด้วย SheetJS 0.18.5 จาก npm ซึ่งมีช่องโหว่ที่รู้จักเมื่ออ่านไฟล์ที่ถูกสร้างมาโจมตี ใช้กับไฟล์ภายในเท่านั้น ระบบจริงควรติดตั้งจาก cdn.sheetjs.com
- เวลาใน Excel ของฟอร์มถือว่าเป็นเวลาไทย

## พัฒนาบนเครื่อง

```bash
npm install
DATABASE_URL=postgres://... npm run dev
npm test                                      # ทดสอบกฎเข้า/ออกและตัวอ่าน Excel
BASE_URL=http://localhost:3000 node --experimental-strip-types scripts/smoke.ts   # ทดสอบทั้งระบบด้วยข้อมูลปลอม
```

`scripts/smoke.ts` เขียนข้อมูลปลอมลงฐานข้อมูล ใช้กับฐานข้อมูลทดสอบเท่านั้น
