# CRL SafeCheck — ต้นแบบ Phase 1 (ตาม Mockup v1)

ต้นแบบสำหรับทดสอบ concept หลัก: ตั้งต้นชุดธงจาก Excel, ตรวจทานธง, รับข้อมูลคนในพื้นที่ (MS Form, KIOS), แจ้งเหตุ → ยืนยันด้วยรหัส, ค้นหาและระบุสถานะคน, เช็คชื่อทั้งธงตอนซ้อม, Safety ระบุผู้บาดเจ็บ และ Dashboard สด

## สถานะคน (ตาม Flow ใน mockup)

| สถานะ | ความหมาย | นับใน % |
| --- | --- | --- |
| ยังไม่ทราบ | ค่าเริ่มต้นของคนที่ “มา” + คนนอกรายชื่อที่เพิ่มระหว่างเหตุ | ผู้สูญหาย |
| ยังอยู่ในคลัง | มีคนเห็น/รู้ว่ายังติดอยู่ → แจ้งทีมกู้ภัย | ผู้สูญหาย |
| ปลอดภัย / บาดเจ็บ / กองอำนวยการกลาง | อพยพแล้ว | อพยพแล้ว |
| ปลอดภัยตามระบบ | คนที่ “ไม่มา” จากหน้าตรวจทาน รอยืนยัน อยู่ท้ายรายการ | ไม่นับ |
| ยืนยันไม่อยู่ | ยืนยันแล้วว่าไม่อยู่ในพื้นที่ | ไม่นับ |

- ธงครบ = ไม่มีคนยังไม่ทราบหรือยังอยู่ในคลัง
- เช็คชื่อทั้งธง (ซ้อมเท่านั้น): จำนวนที่นับได้ต้องตรงกับที่ติ๊ก + ที่ระบุไปแล้ว ติ๊ก = ปลอดภัย ไม่ติ๊ก = คงสถานะเดิม
- ปิดเคสได้เสมอ แต่ระบบเตือนถ้ายังมีปลอดภัยตามระบบที่รอยืนยัน
- snapshot ตอนยืนยัน: ชุดธงปัจจุบัน (หักคนที่ลบ) + คนที่เช็กอินฟอร์ม + รถในลานจาก KIOS ข้อมูลสดดึงตามมาแบบบวกอย่างเดียว ห้ามลบคน ห้ามทับสถานะที่ระบุแล้ว

## Deploy บน Vercel

1. อัปโหลดโฟลเดอร์นี้ขึ้น GitHub (repo แบบ private) ให้ `package.json` อยู่ที่ root ของ repo
2. Vercel → Add New Project → เลือก repo
3. Storage → เพิ่ม Neon (Postgres) → ได้ `DATABASE_URL` อัตโนมัติ
4. Settings → Environment Variables:
   - `ADMIN_PIN` — รหัส Admin ตั้งต้น (ตัวเลข 4–8 หลัก) ใช้เข้าหน้าตั้งค่าครั้งแรกเพื่อเพิ่มผู้ยืนยันและตั้งรหัส
   - `SESSION_SECRET` — ข้อความสุ่มยาว ใช้เซ็น token ของรหัส
   - `APP_USER`, `APP_PASSWORD` — ถ้าตั้ง จะต้องใส่รหัสก่อนเข้าทั้งเว็บ (แนะนำ เพราะมีข้อมูลพนักงาน)
   - `KIOS_BASE_URL`, `KIOS_API_KEY` — เส้น Driver
   - อื่นๆ ดู `.env.example`
5. Deploy (ตารางสร้างและอัปเกรดเองตอนเรียกครั้งแรก ข้อมูลจากต้นแบบเดิมยังอยู่)

หมายเหตุ: region `sin1`, cron วันละครั้งตอน 09:00 เวลาไทย (Hobby) ถ้าต้องการทุก 15 นาทีใช้ตัวตั้งเวลาภายนอก เรียก `GET /api/cron/sync` พร้อม `Authorization: Bearer <CRON_SECRET>`

## ลองใช้ครั้งแรก

1. `/admin` ใส่ `ADMIN_PIN` → ลากไฟล์ธงทั้ง 43 ไฟล์ → ดูผลตรวจ → บันทึกเป็นชุดธง v1
2. ตั้งชื่อจุดรวมพลและจุดสำรอง เพิ่มผู้ยืนยัน (Safety Officer) พร้อมรหัส
3. เปิด `/review` บนมือถือ ตรวจทานทีละธง ติ๊ก มา/ไม่มา แล้วกดยืนยันว่าตรวจแล้ว → กลับ `/admin` กด “บันทึกเป็นชุดธง v2”
4. `/admin` กด “เริ่มซ้อม” → บนมือถือเปิดแอพจะเข้าหน้าค้นหาทันที เลือกธง → เช็คชื่อทั้งธง
5. เปิด `/dashboard` บน PC ดูยอดสด ทดลองบันทึก Code ประกาศ แล้วกดจบการซ้อม
6. ทดสอบเหตุจริง: หน้าแรกเข้าสู่ระบบด้วยรหัสพนักงาน → แจ้งเหตุ → ใส่รหัส Safety ยืนยัน (ปิดจุดรวมพลได้)

## เส้นข้อมูล

- **MS Form (DIV+)** — Flow เขียนลง SharePoint List → แอพดึงผ่าน Graph (ต้องมี app registration `Sites.Selected`) ระหว่างรอ นำเข้า Excel ของฟอร์มที่ `/sources` ได้ ระบบอนุมานเข้า/ออก: ซ้ำใน 10 นาทีนับครั้งเดียว, ครั้งที่สอง = ออก, ต่างไซต์ = ย้ายไซต์, ครบ 14 ชม. = ออกอัตโนมัติ
- **Driver (KIOS)** — เรียก RPC เดียวกับ Power BI ตรง ใช้ทะเบียนรถเป็นตัวระบุ หนึ่งคันหนึ่งคน จำนวนรถลดเกิน 30% ในรอบเดียวถูกกักไว้จนกว่าจะยืนยัน
- **Cnext, Outsource** — ยังไม่เชื่อม ระหว่างนี้ใช้ชุดธงจาก Excel เป็นฐาน

## ข้อจำกัดของต้นแบบ

- login ผู้ใช้ทั่วไปใช้รหัสพนักงานอย่างเดียว (ระบุตัวตน ไม่ใช่ความปลอดภัย) และรหัส Admin/Safety เป็น PIN ระบบจริงควรเปลี่ยนเป็น Sign in with Microsoft
- ธงเป็นตัวเลข (ธงชื่อ Safety / LP ใน mockup ยังไม่รองรับ) และยังไม่มีช่องหัวหน้าธงสำรอง
- อัปเดตหน้าจอด้วยการถามซ้ำทุก 3 วินาที ยังไม่ใช่ realtime และยังไม่มีโหมด offline
- SheetJS 0.18.5 จาก npm มีช่องโหว่ที่รู้จักเมื่ออ่านไฟล์ที่สร้างมาโจมตี ใช้กับไฟล์ภายในเท่านั้น
